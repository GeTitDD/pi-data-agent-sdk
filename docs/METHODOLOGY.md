# 信任阶梯法（Trust-Ladder Method）

> 一套用于**从零构建可信系统**的通用分层方法论。源自 Data Agent SDK 的实践（M0/M1），
> 但目标是与领域无关：数据库、HTTP 服务、编译器、ETL、LLM 应用都适用。

---

## 0. 一句话

> **越往下越"可信"，越往上越"聪明"；最底层只做一件事——成为一个"可用且可信任"的最小单元。**

因为：**智能可以逐层叠加，信任不能。** 底层若说谎，上面全是虚构。

---

## 1. 第一性原理（4 条公理）

**公理 1｜信任不可向上修复。**
上层只能信任下层**明确承诺且被证明**的东西。任何未声明的保证，上层都必须当作不存在。
推论：**保证必须在它最早能被强制的地方给出**（越靠下越好）。

**公理 2｜不可信输入必须在最底层被收编。**
模型输出、用户输入、网络数据……都是不可信输入。收编它们的代码属于**边界层**，不属于业务层。
推论：**边界层是系统里唯一允许与外部世界打交道的地方。**

**公理 3｜每层只解决一个问题，并可被单独验证。**
一个层若不能脱离上层被测试，说明它偷偷耦合了上层。

**公理 4｜依赖只向下，且只依赖"端口"。**
上层 import 下层的**接口**，不 import 实现。具体实现只由最外层注入。

---

## 2. MUTU：最小可用可信任单元

**定义**：MUTU = *Minimal Usable & Trustworthy Unit* —— 在它之上可以安全构建任何东西的最小构件。

三个判据，缺一不可：

| 判据 | 含义 | 反例 |
|---|---|---|
| **可用（Usable）** | 能对**真实外部系统**完成一次真实闭环（不是 mock） | 只有类型定义、没有执行 |
| **可信任（Trustworthy）** | 它的保证**不可被上层绕过**，且**有测试证明** | 文档写"只读"，代码没强制 |
| **最小（Minimal）** | 只做一件事；再拆开就失去独立意义 | 把"连接 + 护栏 + 目录"塞进一个文件 |

**关键**：只满足一半都不行——
- 可用但不可信 → 地基是流沙，**上层越聪明越危险**
- 可信但不可用 → 是个库，不是系统

**在哪里找 MUTU**：去找那条「**不可信输入 → 受控副作用**」的路径。那就是 MUTU 所在的层（通常是 A1）。

---

## 3. 五层阶梯（生物隐喻 + 通用名）

每层是下一层的**组合单元**，并且**只向上暴露端口**。

| 层 | 隐喻 | 通用名 | 单元含义 | 它只做 |
|---|---|---|---|---|
| **A0** | 原子 | 语汇 Vocabulary | 不可再分的值 | 定义类型与纯函数（无 IO、无状态）|
| **A1** | 分子 | 能力 Capability | **可独立成立的最小构件（MUTU）** | 封装外部世界为端口 + 给出保证 |
| **A2** | 细胞 | 变换 Transformation | 一个职责的完整变换 | 输入→输出，不碰基础设施 |
| **A3** | 器官 | 流程 Workflow | 多个细胞协作完成一件对用户有意义的事 | 有状态、可中断、可观测、有明确终止条件 |
| **A4** | 个体 | 宿主与治理 Surface | 与外界打交道的完整个体 | 交付形态、身份权限、可观测性 |
| **A5** | 生态 | 度量 Evaluation | 判断整体是否达标 | 与实现解耦的评测 |

**每层"膜"的概念**：细胞有细胞膜 = 端口。没有膜的东西不是细胞，是组织液（无法替换、无法测试）。

---

## 4. 依赖纪律（可执行的规则）

1. **import 预算**：写 A(n) 层时只允许 import A(n-1) 的**类型/端口**。
2. **禁止跨层 import 实现**：A2 里出现 `import { SqliteAdapter }` 即为违规（应由最外层注入）。
3. **唯一通道**：每层对外只留一个受控入口。**旁路的存在等于整体强度等于最弱路径。**
4. **冻结后才向上**：某层的契约测试全绿才允许在其上构建。
5. **回头只许增，不许改**：上层暴露下层接口不足时，**只新增**方法/字段，不改已有签名，并同步契约测试。
6. **复杂度预算**：每层显式预算（模块数 / 行数 / 依赖数）。超出即为过度设计，回退设计而不是加预算。
7. **呈现类型不得向上污染**：只有“给人看”的东西（主题 / 样式 / 布局 / 文案 / 颜色）属于**最上层（A4）**。
   下层只输出**语义**（如 `status: "denied"`），由上层决定颜色与措辞；或由上层向下注入一个**呈现端口**。
   判据：若一个类型的字段是给人看的（颜色、字号、措辞），它就不该出现在 A2 及以下。
   （本条由 Pi 案例得出，见 [`CASE-PI.md`](./CASE-PI.md) §8。）

## 5. 保证强度分级（最重要的一张表）

**每一层都必须回答：我的保证属于哪一档？兜底在哪一层？**

| 强度 | 机制 | 能否绕过 | 例 |
|---|---|---|---|
| 🟢 **外部强制** | 引擎 / OS / 类型系统 / 权限系统 | **绕不过** | SQLite `readOnly` 句柄；Postgres 只读账号；类型系统禁止传入任意 SQL |
| 🟡 **自身实现** | 自己写的解析/校验/黑名单 | **可能漏** | 正则黑名单；词法抽取表名 |
| 🔴 **文档约定** | 注释、README、"请勿……" | 等于没有 | "调用方应先校验" —— 而代码里没有校验 |

**两条铁律**
- **🟢 优先**：能用外部强制就用外部强制，不要用自觉检查替代。
- **🟡 必须声明**：尽力而为的检查**不得被称为防线**，且**必须指明兜底在哪**（通常是同一层的 🟢）。

---

## 6. 应用流程（6 步）

```
0. 先选一根"真实用例的垂直切片"（否则不知道哪些不变量重要）
1. 定位 MUTU：找出「不可信输入 → 受控副作用」那条路径
2. 为它定义端口 + 不变量清单（每条不变量 ⇒ 至少一个契约测试）
3. 实现适配器，优先用外部强制（🟢）而非自觉检查（🟡）
4. 跑通契约测试 → 冻结接口
5. 自下而上逐层叠加；每层只 import 下一层端口，每层写自己的契约测试
6. 每层复核复杂度预算；上层暴露缺口时"只增不改"地回补下层
```

**第 0 步的说明**：方法是自下而上的，但**起点必须来自一个真实用例**。否则会造出"很干净但没用"的层。
即：**用例定方向，分层定秩序。**

## 7. 跨领域示例（证明通用）

| 领域 | A0 语汇 | **A1 MUTU（边界 + 保证）** | A2 变换 | A3 流程 | A4 宿主 |
|---|---|---|---|---|---|
| **Data Agent** | Value/Row/Result | **只读连接 + SQL 护栏** | 检索→生成→校验→执行→验证→作答 | 问数/探索/口径治理/巡检 | Pi 扩展、API、MCP |
| **HTTP 服务** | DTO | **DB 适配 + 认证 + 输入校验** | usecase（纯编排）| 事务化业务流程 | 路由、中间件、限流 |
| **编译器** | token/AST | **词法+语法（带源码位置）** | 语义分析与类型检查 | 优化与代码生成 | CLI / IDE 插件 |
| **ETL** | record schema | **连接器 + 数据校验器 + 幂等键** | 变换（纯函数）| 调度、回填、重试 | 监控与告警 |
| **LLM 应用** | message/token | **模型端口 + 工具执行沙箱 + 输出校验** | RAG、agent 循环 | 会话与工作流 | 前端与权限 |

注意 A1 的形状总是一样：**一个受控的对外通道 + 一组不可绕过的保证。**

## 8. 反模式清单（皆来自真实事故）

| # | 反模式 | 后果 | 真实来源 |
|---|---|---|---|
| 1 | **跨层直连**（跳过 MUTU） | 边界形同虚设 | 若 A2 直接 `import` 数据库驱动 |
| 2 | **旁路入口**（第二条不受控通道） | 整体强度 = 最弱路径 | postgres-mcp 的 `execute_param_query`（接受任意 SQL 且不校验）|
| 3 | **用约定代替强制** | 保证其实不存在 | postgres-mcp 的 `BEGIN TRANSACTION READ ONLY` 在 psycopg3 隐式事务下失效 |
| 4 | **不标注保证强度** | 把 🟡 当 🟢 用，误以为有防线 | 表名白名单被当成越权防护 |
| 5 | **无上限的循环/重试** | 烧钱、卡死 | 无 `repairAttempts` 的修复循环 |
| 6 | **底层未冻结就横向铺开** | 返工 | 没稳住 L1 就做多库适配、UI |
| 7 | **引入用不上的框架** | 成本 >> 收益 | 线性流程上引 LangGraph |
| 8 | **从零造已有的轮子** | 浪费时间且更容易错 | 自写 SQL 解析器 / 测试框架 |
| 9 | **把大结果集一次读入内存** | OOM | `fetchall()` 无上限 |
| 10 | **无 AST 就宣称"解析安全"** | 漏判 | 只用正则黑名单 |
| 11 | **呈现类型向上污染** | 下层被迫依赖上层；分层失效、下层无法独立测试 | Pi 的 `Theme` 定义在 A4，却被 `core/` 4 处 + `extensions/mcp` 1 处引用 |

## 9. 每层自检三问（评审时必答）

1. **承诺**：这一层对上层承诺什么？这个承诺**能被绕过吗**？
2. **伤害面**：如果这一层实现错了，**谁会受伤**？受伤面越大，它就该越靠下、越该用外部强制。
3. **可测性**：这一层能**脱离上层**被单独测试吗？不能 → 它耦合了上层。

## 10. 与本项目（Data Agent SDK）的对应

| 层 | 本项目 | 保证强度 |
|---|---|---|
| A0 | `atoms.ts`（Value/Row/ExecStatus/ExecResult）| — |
| **A1** | **`guard.ts`（准入判定）+ `adapters/sqlite.ts`（只读执行）** | 护栏 🟡；只读 🟢（引擎强制，绕过也写不进）|
| A2 | `cells.ts` + `ask.ts`（M1）| 确定性变换（同输入同输出）|
| A3 | 问数/探索/治理/巡检（v2）| 可中断、有终止条件 |
| A4 | Pi 扩展面（M2）| 权限贯穿、交付可换 |
| A5 | `test/`（+ 将来 Spider/BIRD 子集）| 与实现解耦 |

**M0 的实质就是把 A0+A1 做成 MUTU**：784 行、零依赖、24 项契约测试冻结。
**M1 的实质是在 A2 上做"确定性流水线"**，并因此发现 A1 需要新增 `introspect()` 端口（**只增不改**的第 5 条规则）。

## 附：一页速记

```
公理：信任不可向上修复 / 不可信输入在最底层收编 / 每层一个问题 / 只依赖下一层端口
核心：MUTU = 最小·可用·可信任  → 它住在「不可信输入 → 受控副作用」那条路径上
纪律：import 只向下 · 唯一通道 · 契约测试冻结后才向上 · 回补只增不改 · 复杂度预算
分级：🟢 外部强制（绕不过） > 🟡 自身实现（可能漏，须声明兜底） > 🔴 文档约定（等于没有）
做法：用例定方向，分层定秩序；先打穿一根真实切片，再自下而上逐层筑牢
```
